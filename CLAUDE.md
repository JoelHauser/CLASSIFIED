# CLASSIFIED: notes for Claude

BepInEx client plugin for SPT 4.1.x: a BEAR or USEC faction terminal over the game's launch, and optionally over raid loads and the way back from a raid. Sister mod of ACCESS GRANTED (`..\ACCESSGRANTED`), built from the same code. Player-facing docs are `README.md` and `MOD-PAGE.md`; this file is for working on it.

## Layout

- `src/CLASSIFIED/ClassifiedPlugin.cs`: config (F12), `PluginVersion`, `OwnsThisLaunch` (ACCESS GRANTED reads it by reflection), and who shows a raid load (Deploy Screen Overhaul and ACCESS GRANTED interplay).
- `Patches.cs`: Harmony hooks on the launch steps, the deploy screen (`MatchmakerTimeHasCome`), the countdown, raid start and the return to the menu.
- `Overlay*.cs`: the terminal (one partial class). `Overlay.Deploy.cs` is the raid load, `.Preview.cs`/`.Showreel.cs` are the Ctrl+F6 preview, `.Debrief.cs`/`Hologram.cs`/`Kit.*.cs` are the kit table.
- `DeployScene.cs`: what is switched off under the raid-loading terminal (see below). **Identical copy in ACCESS GRANTED**: change both, differing only in namespace and `ClassifiedPlugin`/`AccessGrantedPlugin`.
- `Resources/`: embedded art and item models (about 2,300 files; the DLL is about 45 MB). They are generated by the Python scripts in `scripts/` (`armory.py`, `make_*.py`); read a script's header before running it.

## Build and release

- The csproj needs `-p:SPTPath=<SPT root>`, and refuses to build unless `Assembly-CSharp.dll.spt-bak` exists (that is, SPT has patched the DLL). `C:\HUH` on the work laptop is patched (since November 2026), so real builds work there. `-p:CompileCheckOnly=true` skips the check, but those DLLs must never ship.
- Release: `scripts\pack.ps1 -SPTPath C:\HUH` from **PowerShell** (Bash mangles the path). It checks the version and writes `dist\CLASSIFIED-<ver>.zip`.
- The version lives in two places: the csproj `<Version>` and `ClassifiedPlugin.PluginVersion`.
- Zips hold only `BepInEx/plugins/CLASSIFIED.dll`. Never a README.
- GitHub releases (JoelHauser/CLASSIFIED): tag `vX.Y.Z`, title `CLASSIFIED X.Y.Z`, notes start with the hero image (`docs/images/hero-v4.webp`), then "New in", "Install", and end with `*Конец связи. Out.*`. Untested builds go out as pre-releases with " (pre-release)" in the title and a "Test build" line.
- To read game code: `ilspycmd -t <Type> C:\HUH\EscapeFromTarkov_Data\Managed\Assembly-CSharp.dll`, or `-p -o <dir>` for the whole thing (a few minutes).

## Raid loads: DeployScene

While this terminal covers a raid load (`DeployScene.Cover` from `BeginDeploy`, `Uncover` from `Hide` and `GrantDeploy`):

- The game's `MatchmakerTimeHasCome.ShowPlayerModel` (a turntable PMC) is skipped.
- Once the intro is over (`Covered`, every frame from `WatchDeploy`): the menu's `EnvironmentUI` scene and camera go off (`EnvironmentUIRoot.SetCameraActive`, not `ShowCameraContainer`, which would switch the game's main camera on). The deploy screen, final countdown, `MenuTaskBar` and `_bottomPanelBackground` stop drawing: their Canvas is disabled, or a disabled Canvas is added and destroyed afterwards.
- Setting **Frame Rate While Loading Raids** (Unlocked by default, which changes nothing). The user's rule: **the default must never lower FPS**. A 30/20/15 limit raises the `JobScheduler` force-mode multiplier (the game's loader runs `FrameTicks/2 * multiplier` per frame; the game uses 3) and `Application.backgroundLoadingPriority`. Both are restored on Uncover, the priority only if nothing changed it since.
- On Uncover, the canvases always come back. The background and the model come back only if `TimeHasCome`/`FinalCountdown` is still the current screen and the raid has not started: anywhere else the game sets the environment itself.
- The deploy screen keeps running underneath. The terminal never takes input; Esc calls `AbortMatching` while the game allows cancelling.
